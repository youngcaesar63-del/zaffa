# زَفّة — منصة دعوات زفاف إلكترونية

موقع دعوات زفاف بأصول وتصميمات أصلية، وله نسختان:

| النسخة | التقنية | تُشغَّل أين |
|---|---|---|
| **التشغيل المحلي** | Node.js (بلا أي حزم خارجية) | فورًا — تعمل في المعاينة |
| **نسخة PHP** | PHP 8 + MySQL | تحتاج اختبارًا على الاستضافة الفعلية قبل النشر |

---

## ١. التشغيل السريع (نسخة Node)

```bash
cd zaffa
node server/server.js
```

ثم افتح `http://localhost:3000`

> **لا تحتاج `npm install`** — المشروع يستخدم مكتبات Node القياسية فقط.

### متغيرات البيئة (اختياري)
استخدم `.env.example` مرجعًا للأسماء، ثم صدّر المتغيرات من بيئة التشغيل. لا يقرأ خادم Node ملف `.env` تلقائيًا:

```bash
PORT=3000 \
STRIPE_SECRET_KEY=sk_test_xxx \
PUBLIC_URL=https://yourdomain.com \
node server/server.js
```

**بدون `STRIPE_SECRET_KEY`** لا يتوفر الدفع بالبطاقة. التفعيل التجريبي المجاني متاح فقط إذا ضُبط `ALLOW_DEMO_CHECKOUT=true` على بيئة اختبار معزولة.

## ٣. نموذج الأمان: مفتاح التعديل

لا يحتاج مالك الدعوة إلى حساب دخول؛ عند إنشاء دعوة يُولَّد:

- `id` — معرّف قصير عام (8 أحرف) يظهر في الرابط
- `k` — مفتاح سري (32 حرفًا) يُحفظ في `localStorage` وفي رابط لوحة التحكم

عمليات إدارة الدعوة الخاصة بالعميل تتطلب `k` عبر:
- **query**: `?k=...`
- **header**: `x-edit-key: ...`

لوحة `/admin` محمية باسم مستخدم وكلمة مرور وجلسة؛ لم يعد مفتاح الإدارة القديم صالحًا.

> ⚠️ **مهم:** رابط لوحة التحكم `?id=..&k=..` هو **بيانات اعتمادك**. من يملكه يملك الدعوة. لا تشاركه.

## ٥. النشر على Hostinger (نسخة PHP)

### الخطوة ١: قاعدة البيانات
1. من hPanel → **Databases** → **MySQL Databases**
2. أنشئ قاعدة بيانات (مثلًا `zaffa`) ومستخدمًا لها
3. افتح **phpMyAdmin** واستورد `php/schema.sql`

### الخطوة ٢: الملفات
ارفع إلى `public_html` بهذا الشكل:

```
public_html/
├── index.html            ← من public/
├── create.html           ← من public/
├── dashboard.html        ← من public/
├── done.html             ← من public/
├── admin.html            ← من public/
├── invite.html           ← من public/  (القالب — لازم يكون هنا)
├── assets/               ← من public/assets/  (الصور، الخطوط، الموسيقى، CSS، JS)
│
├── api.php               ← من php/
├── lib.php               ← من php/
├── invite.php            ← من php/
├── og.php                ← من php/
├── config.php            ← من php/
└── .htaccess             ← من php/
```

> **الأسهل:** انسخ محتويات `public/` ثم محتويات `php/` إلى نفس المجلد `public_html`.

### الخطوة ٣: الإعدادات
عدّل `config.php`:

```php
'admin_auth_file' => '/مسار-خاص-خارج-public_html/admin-auth.json',
'public_url' => 'https://yourdomain.com',
'db' => [
    'host' => 'localhost',
    'name' => 'u123456_zaffa',      // اسم القاعدة من hPanel
    'user' => 'u123456_zaffa',      // المستخدم
    'pass' => 'كلمة-المرور',
],
'stripe_key' => '',                // أدخل مفتاح Stripe فقط بعد إعداد الدفع الحقيقي
'stripe_webhook_secret' => 'whsec_xxx',
```

### الخطوة ٤: Stripe
1. أنشئ حسابًا على [stripe.com](https://stripe.com)
2. **Developers → API keys** → انسخ `Secret key`
3. **Developers → Webhooks → Add endpoint**:
   - URL: `https://yourdomain.com/api/stripe/webhook`
   - Events: `checkout.session.completed`, `checkout.session.async_payment_succeeded`
   - انسخ `Signing secret` إلى `stripe_webhook_secret`

### الخطوة ٥: SSL
hPanel → **Security → SSL** → فعّل الشهادة المجانية، ثم أجبر HTTPS.

## تغيير ألوان الموقع — لوحة «شامبانيا وفحم»

هوية الموقع (الصفحات التسويقية ولوحات التحكم) **مركزية بالكامل**.
كل الألوان في مكان واحد: أول `:root` في `public/assets/base.css`.

```css
:root{
  --rose:#a8874f;        /* اللون الأساسي (الذهبي) */
  --rose-dk:#8c6d3a;     /* أغمق — للتدرّجات */
  --rose-deep:#5f4823;   /* الأعمق — للعناوين */
  --rose-soft:#f4efe4;   /* خلفية ناعمة */
  --gold:#b08d4e; --gold-lt:#e0c793; --gold-dk:#7d6130;
  --ink:#221f1a;         /* لون النص الأساسي */
  --ink-2:#565047; --ink-3:#8a8375;
  --bg:#faf8f3;          /* خلفية الصفحة */
  --line:#ece5d7;        /* الحدود */
  --tint-1:#faf6ee; --tint-2:#f3ecdd; --line-2:#e3d9c4;
  --grad-primary:linear-gradient(135deg,#bfa068,var(--rose) 42%,var(--rose-dk));
  --grad-deep:linear-gradient(135deg,var(--rose-dk),var(--rose-deep) 55%,#3e2e14);
  --ok:#3f7a5c; --warn:#a1752a; --err:#b4453f;
}
```

**لتغيير الهوية كلها:** عدّل هذه القيم فقط — لا يوجد أي لون مكتوب يدويًا في
`index.html` أو `create.html` أو `done.html` أو `dashboard.html` أو `admin.html`.
(تحقق: `grep -o "#[0-9a-fA-F]\{6\}" public/*.html` → لا نتائج)

| الملف | ما يحتاج تعديلًا عند تغيير الهوية |
|---|---|
| `public/assets/base.css` | المتغيّرات أعلاه — يكفي |
| `public/assets/logo.svg` | ألوان الخاتمين |
| `public/index.html` | `<meta name="theme-color">` |
| `public/assets/themes.css` | **لا** — لوحات القوالب مستقلة ومقصودة |

> **القوالب مستقلّة عن هوية الموقع.** كل قالب من الـ١٩ له لوحته الخاصة
> (`THEMES` في الخادم + `body.t-*` في `themes.css`) لأن الدعوة تخصّ العميل
> لا البراند. تغيير هوية الموقع لا يغيّر ألوان الدعوات.

### بنك العبارات — `public/assets/phrases.js`

لكل قالب نبرة لغوية خاصة، تُستخدم في:
- **سطر الدعوة** على الغلاف (من `THEMES` في الخادم)
- **كلمة الترحيب** — زر «✨ اقترح كلمة تناسب القالب» في صفحة الإنشاء
- **عبارة الختام**

لإضافة نبرة جديدة: أضف مفتاح القالب في `PHRASES` و`THEME_FONTS`.

### إضافة قالب جديد
1. ضع صورة الغلاف في `public/assets/hero/{id}.webp` (1400px عرضًا، WebP q82 ≤ 300KB)
2. أضف الثيم في `server/server.js` (`THEMES`) و`php/lib.php` (`themes()`) بما فيه `hero`
3. أضف كتلة `body.t-{id}` في `public/assets/themes.css` (الغلاف، الإطار، الختم، العدّاد، الحركة)
4. أضف زخرفة وفاصلًا في `ORNAMENTS` و`DIVIDERS` داخل `public/invite.html`
5. أضف نبرة في `public/assets/phrases.js` وخيارًا في `THEME_FONTS`
6. أضفه في `public/create.html` (`TEMPLATES`) و`public/index.html` (شبكة القوالب)
7. أضف لوحة ألوان في `public/assets/card.js` (`PALETTES`)

> الهوية تُمرَّر للعميل عبر `theme.id`، ويطبّقها `applyTemplateIdentity()`.
> القالبان `saudi-m`/`saudi-w` يستخدمان الهويتين `men`/`women` (خريطة `TPL_IDENTITY`).

## ٧. اختبارات سابقة وحدودها

النتائج أدناه تخص بيئة Node محلية معزولة، ولا تثبت نجاح النشر أو الدفع الحقيقي. بعض الاختبارات تاريخية وقد تحتاج إعادة تشغيل بعد التعديل.

| الاختبار | النتيجة |
|---|---|
| كل مسارات الموقع | ✅ 200 |
| إنشاء دعوة → دفع → تفعيل | ✅ يعمل |
| RSVP + دفتر تهاني | ✅ يعمل |
| لوحة التحكم + تصدير CSV | ✅ يعمل |
| مولّد كرت PNG | ✅ 1080×1620 |
| صلاحيات: أمثلة لمفتاح التعديل الخاطئ | ✅ رُفضت في اختبارات Node المحلية |
| path traversal | ✅ 404 |
| rate limiting | ✅ يعمل |
| نسخة PHP وMySQL | لم تُختبر رحلتها كاملة على MySQL فعلي؛ اختبارات مستقلة للصياغة والمصادقة فقط |
| صورة OG: توليد → رفع → خدمة → meta | ✅ PNG 1080×1620 |
| القالب السابع (الشام) | ✅ في البيع + الإنشاء + الكرت |
| الموسيقى الجديدة | ✅ 47ث + 35ث |
| أخطاء console | ✅ صفر |

## ٨. صورة المشاركة على واتساب (OG)

### كيف تعمل
1. بعد الدفع، صفحة `/done` ترسم **كرت الدعوة PNG** في المتصفح (`assets/card.js` → Canvas)
2. ترفعه إلى `POST /api/invites/{id}/og` بمفتاح التعديل
3. الخادم يخزّنه في `data/og/{id}.png` ويخدمه على `/og/{id}.png`
4. صفحة الدعوة تضع `<meta property="og:image" content=".../og/{id}.png">`
5. تطبيق المشاركة قد يعرض الصورة بعد جلب الرابط؛ يعتمد ذلك على دعمه للتنسيق والكاش.

### لماذا في المتصفح وليس على السيرفر؟
تشكيل الحروف العربية داخل Canvas على السيرفر يحتاج `libraqm` — وهو غير متاح على معظم الاستضافات المشتركة. المتصفح يفعل ذلك بشكل مثالي مجانًا.

### تحديث الصورة بعد تعديل البيانات
في صفحة `/create` (بعد التفعيل) تظهر بطاقة **«صورة المشاركة»** مع معاينة وزر تحديث.

### على نسخة PHP
تُحفظ صورة PNG خارج جذر الموقع في `ZAFFA_OG_DIR`، ويخدمها `og.php` للدعوة المفعّلة فقط، مع SVG بديل إذا لم تُرفع صورة بعد. يلزم اختبار ذلك على استضافة Apache/MySQL فعلية قبل النشر؛ بعض تطبيقات المشاركة لا تدعم SVG.

### ملاحظة مهمة عن الكاش
واتساب يخزّن صورة المشاركة. بعد تحديثها، استخدم
[Facebook Sharing Debugger](https://developers.facebook.com/tools/debug/) واضغط **Scrape Again** لمسح الكاش.

## ٩. الحدود المعروفة

- **نسخة Node** تخزّن في ملف JSON (`data/db.json`) — مناسبة للتجربة والمشاريع الصغيرة. للإنتاج استخدم نسخة PHP.
- **Stripe** يحتاج مفاتيحك وحسابًا مفعّلًا للدفع الحقيقي.
- **بنكك** التحويل يدوي بطبيعته — تأكيد التحويل يتم من `/admin`.
- صورة OG تُولَّد **في المتصفح** وترفع للسيرفر — راجع القسم ٦ أدناه.

```
├── data/                     ← بيانات نسخة Node (تُنشأ تلقائيًا)
├── .env.example
└── package.json
```

### تحديث قاعدة البيانات لإصلاح تعديل رد الحضور
للتثبيت الجديد يتضمن `php/schema.sql` العمود المطلوب. أما قواعد MySQL الموجودة مسبقًا، فخذ نسخة احتياطية ثم نفّذ `php/migrate_rsvp_edit.sql` مرة واحدة قبل نشر نسخة PHP المحدثة. لا تُنفّذ الترحيل على قاعدة جديدة تتضمن العمود بالفعل. يسمح زر «تعديل الرد» بتعديل الرد خلال الجلسة الحالية في صفحة الدعوة؛ بعد إعادة تحميل الصفحة يبدأ رد جديد.

### اختبارات رحلة المستخدم المعزولة
الاختبارات في `tests/` تتطلب Python وPlaywright مع متصفح Chromium مثبت، وتُنشئ دعوات اختبار؛ لا تشغّلها على بيانات إنتاجية. في بيئة اختبار منفصلة شغّل:

```sh
PORT=3011 DATA_DIR=/tmp/zaffa-test-data SD_ACCOUNT=123456 SD_FAWRY_ACCOUNT=234567 SD_OCASH_ACCOUNT=345678 SD_NAME=Test SD_WHATSAPP=249111111111 ALLOW_DEMO_CHECKOUT=true node server/server.js
```

ثم من نافذة أخرى شغّل `python3 tests/user_journey_demo.py` و`python3 tests/user_journey_bank.py` و`python3 tests/user_journey_music.py`. اختبار بنكك يستخدم أرقامًا وحساب إدارة تجريبيًا؛ جهّزه أولًا بالأمر `python3 tests/prepare_test_admin.py /tmp/zaffa-test-data`. عند الانتهاء أوقف الخادم واحذف مجلد بيانات الاختبار فقط. هذه الاختبارات لا تنفّذ دفعًا حقيقيًا أو إرسال واتساب فعليًا.

### رفع موسيقى خاصة
يمكن لصاحب الدعوة اختيار ملف MP3 من جهازه (حتى ٨ ميغابايت) والاستماع إليه قبل الحفظ. عند حفظ الدعوة يُرفع الملف، وتُشغّل النسخة المحفوظة لضيوف الدعوة. استخدم فقط موسيقى لديك حقوق استخدامها. الملف متاح لمن يصل إلى رابط الدعوة، فلا ترفع ملفًا خاصًا. يمكن استبداله بملف آخر أو اختيار مقطع من المكتبة.

في Node تُحفظ الملفات في `DATA_DIR/music`؛ ضمّن المجلد في النسخ الاحتياطي. في PHP يُستخدم المسار خارج جذر الموقع `../zaffa-private/music` افتراضيًا، ويمكن تغييره بمتغير البيئة `ZAFFA_MUSIC_DIR`. تأكد من قابلية المجلد للكتابة ومن إعدادات خادم الويب التي تسمح بطلبات بحجم ٨ ميغابايت. اختيار مقطع آخر لا يحذف الملف المرفوع من التخزين تلقائيًا.

اختبار ضغط HTTP المحلي: شغّل خادمًا معزولًا ببيانات منفصلة على المنفذ 3013 ثم نفّذ `python3 tests/load_test.py`. ينشئ الاختبار دعوة ومئات الردود، ويُحاكي عناوين ضيوف عبر ترويسة `X-Forwarded-For`. لا تشغّله على بيانات حقيقية أو على خادم إنتاجي. نتائج localhost لا تمثل أداء الاستضافة أو قدرة النظام المستدامة.

### عنوان العميل والوسيط العكسي في Node
افتراضيًا يتجاهل Node ترويسة `X-Forwarded-For` ويستخدم عنوان الاتصال المباشر لحدّ المعدل. خلف وسيط عكسي فقط، اضبط `TRUSTED_PROXY_IPS` إلى عناوين IP الفعلية للوسطاء الذين يصلون مباشرة إلى الخادم، مفصولة بفواصل؛ يُستخدم آخر عنوان في الترويسة. يجب أن يضيف الوسيط عنوان العميل الحقيقي أو يستبدل الترويسة، وأن يُمنع الوصول المباشر من الجمهور إلى Node. لا تضف عنوانًا غير موثوق. إذا لم تُضبط القائمة فقد يُطبّق حد المعدل على جميع الزوار بعنوان الوسيط نفسه. نسخة PHP تستخدم `REMOTE_ADDR` وتعتمد على إعدادات الاستضافة.

لتشغيل `tests/load_test.py` في بيئة محلية معزولة تُحاكي وسيطًا، شغّل خادم الاختبار مع `TRUSTED_PROXY_IPS=127.0.0.1`؛ لا تستخدم هذا الإعداد لمحاكاة عناوين في الإنتاج.

### الرقم المرجعي للدعوة والتحويل
كل دعوة تحصل على رقم مرجعي ثابت عند إنشائها، وهو مختلف عن معرّف الرابط ومفتاح الإدارة. تظهر الأرقام في لوحة الإدارة، ويمكن البحث بها، كما يظهر الرقم للعميل في شاشة بنكك قبل التحويل مع زر نسخ وطلب كتابته في ملاحظة التحويل. التفعيل بعد التأكد يدويًا من وصول المبلغ؛ الرقم وحده ليس إثبات دفع. إلغاء شاشة بنكك لا يحذف الدعوة المسودة أو يعيد استخدام رقمها.

لقاعدة PHP/MySQL جديدة يتضمن `php/schema.sql` الرقم المرجعي. لقواعد MySQL القائمة: خذ نسخة احتياطية، ثم نفّذ `php/migrate_invite_reference.sql` مرة واحدة قبل نشر الكود. تُرقّم الدعوات القديمة تلقائيًا؛ تحقّق من الأرقام بعد الترحيل. في Node تُرقّم الدعوات القديمة عند أول تشغيل للنسخة الجديدة، ويُحفظ العداد مع البيانات. استخدم عملية Node واحدة فقط لكل مجلد بيانات؛ تخزين JSON غير مصمم لتزامن عدة عمليات خادم أو أجهزة.

### قفل الدعوة قبل التفعيل وتأكيد الدفع
المعاينة داخل صفحة الإنشاء متاحة باستخدام بيانات تجريبية. الدعوة الفعلية والردود والتهاني وصورة المشاركة والصوت المرفوع ليست متاحة للضيوف قبل التفعيل؛ تبقى لوحة المالك ومعاينة التصميم متاحتين. التحويل البنكي يُفعّل يدويًا بعد مطابقة المبلغ والرقم المرجعي. يؤدي زر «إيقاف» الإدارة إلى حظر الدعوة مجددًا؛ لا يمكن استرجاع الصور أو الرسائل التي سبق مشاركتها أو منع النسخ المخزّنة مؤقتًا لدى الآخرين.

يتطلب تفعيل Stripe الحقيقي ضبط `STRIPE_SECRET_KEY` و`STRIPE_WEBHOOK_SECRET` مع تسجيل حدثي `checkout.session.completed` و`checkout.session.async_payment_succeeded` في Stripe. يرفض الخادم التفعيل إن لم تطابق الجلسة الدعوة أو لم يُثبت الدفع؛ ويحتاج رابط التحقق إلى `x-edit-key`. لم تُختبر مدفوعات Stripe الحقيقية، ويجب اختبارها في بيئة Stripe الاختبارية ثم الإنتاجية قبل الإطلاق. لا تشارك المفاتيح السرية في المحادثات؛ ضعها في إعدادات الاستضافة الآمنة.

### التحويل المحلي — بنكك وفوري وأوكاش
تتوفر طرق التحويل الثلاث بسعر ٢٠٬٠٠٠ جنيه سوداني للدعوة. يعرض الموقع الحساب الذي يختاره العميل ويطلب إدخال رقم العملية والاسم وكتابة الرقم المرجعي في ملاحظة التحويل إن توفرت. طلب واتساب يفتحه العميل؛ لا يعني إرسال الرسالة أو إدخال البيانات أن التحويل تم، ويتحقق المدير من وصول المبلغ إلى الحساب الصحيح قبل التفعيل. تُعرض طريقة التحويل في الإدارة. القيم قابلة للتعديل بمتغيرات البيئة `SD_ACCOUNT` و`SD_FAWRY_ACCOUNT` و`SD_OCASH_ACCOUNT` و`SD_NAME` و`SD_WHATSAPP` و`SD_PRICE` (بالقرش).

لم يعد الدفع التجريبي المجاني متاحًا افتراضيًا: لا يُفعّل المسار التجريبي إلا بتعيين `ALLOW_DEMO_CHECKOUT=true` على خادم اختبار معزول. في الإنتاج لا تضبط هذا الخيار. لا يظهر الدفع بالبطاقة ما لم يُضبط مفتاح Stripe وسر webhook. لتحديث قاعدة MySQL القائمة أجرِ نسخة احتياطية ونفّذ `php/migrate_payment_method.sql` مرة واحدة، إضافةً إلى ترحيلات الإصدار السابقة إن لم تكن قد نُفذت. لم يُختبر الترحيل على استضافة MySQL فعلية بعد.

### حساب المدير
تسجيل الدخول من `/admin` باسم المستخدم وكلمة المرور. تُخزّن تجزئة مملّحة فقط في ملف `data/admin-auth.json` لنسخة Node، أو خارج جذر الموقع في `../zaffa-private/admin-auth.json` لنسخة PHP؛ لا ترفع هذا الملف ضمن `public/`. الجلسة عبر ملف ارتباط HttpOnly وSameSite=Strict وتنتهي بعد ٨ ساعات؛ يطلب الخادم HTTPS عند النشر لضمان خاصية Secure. يمكن تغيير كلمة المرور من لوحة الإدارة؛ هذا ينهي الجلسات القديمة.

لإنشاء الحساب أو إعادة تعيينه من طرفية موثوقة: `node scripts/set-admin.js admin /المسار/الخاص/admin-auth.json`. سيطلب كلمة المرور دون إظهارها؛ غيّر المسار ليطابق `ZAFFA_ADMIN_AUTH_FILE` أو مسار بيانات Node. لنسخة PHP على استضافة لا تدعم Node، أنشئ الملف على جهاز موثوق وانقله خارج جذر الموقع بطريقة آمنة، أو اضبط المسار في إعدادات الاستضافة. لا تشارك كلمة المرور أو ملف الحساب. إعادة تشغيل Node تبطل جلسات الإدارة. لا تزال نسخة PHP/MySQL تحتاج اختبارًا على استضافة فعلية.
